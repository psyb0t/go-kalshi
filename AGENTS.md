# go-kalshi

Unofficial Go client for Kalshi, generated from the API specs Kalshi publishes. If you only want to use the client from an agent, read [.agents/skills/go-kalshi/SKILL.md](.agents/skills/go-kalshi/SKILL.md) instead; this file is about changing the code.

## Architecture

Three generated packages, each driven by its own `gen.go`, plus one hand-written one:

- REST, package `kalshi` at the root: `scripts/fetch-spec.sh openapi.yaml` downloads Kalshi's OpenAPI document into `api/` → oapi-codegen with `config.yaml` and `overlay.yaml` → `client.gen.go`.
- Market data WebSocket, package `kalshiws` in `ws/`: `scripts/fetch-spec.sh asyncapi.yaml` → `scripts/match-client-spec.sh asyncapi.yaml` writes `api/asyncapi.client.yaml` → gen-asyncapi with `ws/config.yaml` → `ws/kalshiws.gen.go`.
- Perps WebSocket, package `kalshiperpsws` in `perpsws/`: the same steps with `perps_asyncapi.yaml` → `perpsws/kalshiperpsws.gen.go`.
- Signing, package `kalshiauth` in `auth/`: hand-written RSA-PSS and Ed25519 request signing for REST and the WebSocket handshakes.

## Stack

- Go 1.26.9.
- oapi-codegen (REST) and gen-asyncapi (WebSocket), both pinned as `tool` dependencies in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`, `github.com/psyb0t/gen-asyncapi/asyncapirt`, `github.com/psyb0t/ctxerrors`.

## Layout

- `gen.go`, `config.yaml`, `overlay.yaml`, `client.gen.go`: the REST package. `client_test.go` and `readme_test.go` test it.
- `ws/`, `perpsws/`: the WebSocket packages, their configs and tests. `ws/testdata/` holds real-shaped frames.
- `auth/`: the signer and its tests.
- `scripts/`: spec download, the client-side spec patch, lint and security scan scripts.
- `api/`: downloaded specs, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the specs and regenerate the three packages
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Kalshi's AsyncAPI documents describe the server. Without `match-client-spec.sh` swapping `send` and `receive`, gen-asyncapi builds a server instead of a client.
- The shared market ticker pattern in Kalshi's spec rejects real tickers with a dot; `match-client-spec.sh` drops it. Lose that step and real frames fail validation.
- `make generate` always downloads Kalshi's current specs, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- The signature covers the URL path without the query string. Signing `req.URL.String()` or `RequestURI` breaks every request with query parameters.
- Kalshi reuses names across component sections, so `config.yaml` turns on `resolve-type-name-collisions` and some response wrappers get a `2` suffix (`GetBalanceResponse2`).
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
